# stat-export — подготовка сессии к stat-me

Надстройка над [stat-me](../stat-me/SKILL.md), не замена. Вариант `index-me` для экспортов OpenCode: не читать огромный JSON, а построить индекс и подтягивать только нужные куски. **Итоговый STAT.md пишет stat-me.**

## Устройство

`scripts/stat_export.py` — тонкая точка входа, вся логика в `scripts/statexp/`:

- `model.py` — нормализация `info` + `messages` в обмены;
- `metrics.py` — единственное место, где считаются флаги, ошибки, дубли, токены и трение;
- `render.py` — общие таблицы/форматирование;
- `skills.py`, `db.py` — внешние источники (каталоги скиллов и, факультативно, БД);
- `cache.py` — кэш и указатель;
- `cli.py` — только аргументы и диспетчеризация;
- `sections/` — по одному модулю на срез, реестр в одном файле.

Добавить срез = новый модуль + одна строка в реестре. Секции сами ничего не считают: читают `Metrics`.

## Что получается

Всё временное лежит в `/tmp/stat-export/`: `cache.json`, готовые `*.md` по срезам и `digest.md` в `/tmp/stat-export/<key>/`, указатель `/tmp/stat-export/<session>.export.md` с путём к кэшу и командами, сам экспорт сессии. `.tmp` stat-export не трогает: там остаётся только итоговый STAT.md, который пишет stat-me. После stat-me временные файлы удаляются (`clean`).

## Порядок работы

1. `python3 <skill>/scripts/stat_export.py <session.json> build`.
2. Прочитать указатель, затем `digest` (обзор + индекс + проблемы + цепочки + контекст + скиллы + трение).
3. По флагам и номерам обменов взять нужные срезы.
4. **Сразу, без паузы и без дополнительного запроса, запустить stat-me**: загрузить его SKILL.md, отдать факты, дождаться STAT.md в `.tmp/stats/<название>.md`. stat-export считается завершённым только после stat-me — останавливаться на срезах нельзя.
5. Убрать временные файлы: `python3 <skill>/scripts/stat_export.py <session.json> clean`. Детали жёстких правил стыка — в «Связи со stat-me» ниже.

Сырой экспорт целиком не читать.

## Текущий чат без ручного `/export`

Если просят что-то вроде «stat-export current chat pls», сессию берём из переменной окружения `OPENCODE_SESSION_ID` — она указывает именно на текущий чат. Никаких `session list | head -1`: там может оказаться более свежая чужая сессия. `--sanitize` не использовать никогда.

```sh
test -n "${OPENCODE_SESSION_ID:-}" || { echo "Не могу определить ID текущей сессии — экспортируйте вручную" >&2; exit 1; }
SID="$OPENCODE_SESSION_ID"
TMP="/tmp/stat-export"
mkdir -p "$TMP"
opencode session export "$SID" > "$TMP/session-$SID.json"
python3 <skill>/scripts/stat_export.py "$TMP/session-$SID.json" build
python3 <skill>/scripts/stat_export.py "$TMP/session-$SID.json" digest
```

`> "$TMP/..."` — все временные файлы в `/tmp/stat-export/`; имя файла содержит ID, поэтому чаты не перезаписывают друг друга. `.tmp` stat-export не трогает. Пустой ID → спросить пользователя, не угадывать.

Экспорт — снимок на момент вызова: последний ответ ассистента на эту просьбу в него не попадёт, это нормально.

## Команды

`<skill>` во всех командах — базовый каталог скилла, где лежит этот `SKILL.md`.

| команда | что отдаёт |
| --- | --- |
| `build` | пересобрать кэш и указатель |
| `clean` | удалить временные файлы сессии из `/tmp/stat-export/` (вызывать после stat-me) |
| `digest` | стартовая сводка |
| `index` | обмены: время, токены, стоимость, длительность, флаги |
| `problems` | аномалии с доказательствами и подсказкой среза |
| `chains [--flagged] [--top N]` | запрос → решение агента → вызовы → результат |
| `context [--top N]` | топ ассистентских сообщений, рассуждений, выводов, запросов; токены по роли |
| `tools [--name N] [--only summary\|errors\|duplicates\|size]` | аналитика инструментов |
| `reasoning [--top N]` | длинные рассуждения, обмены без ответа |
| `errors [--only grouped\|raw]` | ошибки свернуты по сигнатурам (тип + текст) или полный лог |
| `timeline` | долгие обмены, паузы, лаги |
| `skills [--skills-dir DIR]` | использованные скиллы и кандидаты на пропуск |
| `friction [--top N]` | правки пользователя и колебания агента (RU/EN), проверочные прогоны, паузы |
| `enrichment` | факультативные факты из БД: по умолчанию сообщение, что БД не подключена |
| `turn N [--cap N]`, `search 'phrase'`, `path`, `sections` | срез обмена, поиск, путь, список |

Общие флаги `-o/--out`, `--db`, `--db-path`, `--skills-dir` работают до и после подкоманды.

## Важные края

- **БД не трогается по умолчанию.** Экспорт JSON покрывает >90% данных и остаётся единственным источником. `--db` (или `--db-path PATH`) включает обогащение вручную: slug/version, дочерние сессии, компакцию, счётчики todo/event/job. Читаются только сессионные таблицы, не account/credential/blob.
- Скиллы ищутся в `.opencode/skills` и `~/.config/opencode/skills`, а также в `.agents/skills` и `~/.agents/skills` (дефолты skills.sh); `--skills-dir` добавляет каталог. Раздел `skipped` — эвристика по совпадению слов в `USE WHEN` (слова должны встретиться вместе в двух обменах), не факт.
- `friction` разделяет реплики пользователя и рассуждения агента; словари английские и русские.
- Флаги из `index` — указатели, а не вердикт: подтверждать срезом `turn N`.
- `turn` режет поле по `--cap` (по умолчанию 8000 симв.). При изменившемся экспорте зови `build` явно.

## Связь со stat-me

stat-export не пишет STAT.md, не решает, что считать слабым местом, и не формулирует идеи. Он превращает длинный лог в короткие проверяемые факты и **сам запускает stat-me** как финальный шаг: не «если попросят», а автоматически, сразу после срезов. stat-me был пропатчен: он отправляет большие экспорты сюда и возвращает агента к шаблону STAT.md.

Два жёстких правила стыка:

- **stat-export в Навыки.** Вызов был прямым (`@stat-export` / `skill`), в данных экспорта сессии его нет и из среза `skills` он не появится. Вписать в **Использованы** раздела `Навыки` STAT.md вручную: `stat-export — прямой вызов (подготовка сессии к разбору)`. Не ждать, что он выведется сам.
- **Уборка после stat-me.** Tmp-файлы живут только в `/tmp/stat-export/`. После того как stat-me записал STAT.md, выполнить `clean`: всё временное удаляется, в `.tmp` остаётся только итоговый STAT.md.
